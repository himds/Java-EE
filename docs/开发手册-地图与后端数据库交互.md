# 开发手册：前端地图与后端、数据库的交互

本文档说明前端地图如何通过 REST API 与后端、MySQL 数据库配合工作。

---

## 1. 整体数据流

```
浏览器 (Leaflet 地图 + app.js)
    │  HTTP GET + JSON
    ▼
REST API (CommuneResource, HealthResource)
    │  Service → DAO
    ▼
MySQL (waterdb: communes, prelevements, resultats_analyses)
```

- **前端**：`frontend/app.js` 使用 `API_BASE + 路径` 发起 `fetch`，拿到 JSON 后渲染地图、侧栏、弹窗。
- **后端**：Tomcat 部署 WAR，Jersey 映射 `/api/*`，`CommuneResource` 提供各端点。
- **数据库**：DAO 层用 `Database.getConnection()` 读三张表，不直接暴露给前端。

---

## 2. 前端行为与后端接口对应表

| 前端行为 | 请求 | 后端方法 | 数据库/逻辑 |
|----------|------|----------|-------------|
| 打开地图（默认：区域/市镇着色） | `GET /api/map-data?mode=regions&year=...&pollutant=...` | `CommuneResource.getMapData` | `CommuneDao.findAll` + `PrelevementDao.findLatestByCommuneAndFilters` → 按市镇着色 |
| 打开地图（市镇多边形） | `GET /api/communes?year=...&pollutant=...` | `CommuneResource.getAll` | 同上，返回市镇列表；前端用 GeoJSON 匹配 INSEE 画多边形 |
| 打开地图（市镇点） | `GET /api/communes?year=...&pollutant=...` | `CommuneResource.getAll` | 同上；前端用 GeoJSON 质心或 API 的 lat/lon 画圆点 |
| 搜索框输入 | `GET /api/search?q=...&year=...&pollutant=...` | `CommuneResource.search` | `CommuneDao.search` → 名称模糊匹配 |
| 点击某市镇看详情 | `GET /api/latest/{codeInsee}?year=...&pollutant=...` | `CommuneResource.getLatestPrelevement` | `PrelevementDao.findLatestByCommuneAndFilters` → 最新一次采样 + 颜色/结论 |
| 查看某次采样的指标 | `GET /api/details/{prelevementId}` | `CommuneResource.getDetails` | `AnalysisResultDao.findByPrelevementId` → resultats_analyses 列表 |
| 健康检查 | `GET /api/health`、`GET /api/health/db` | `HealthResource` | 仅 DB 检查时连 MySQL |

---

## 3. 前端 API 地址配置

- 默认：`http://localhost:8081/water-quality/api`（本机 RunServer / Cargo）。
- Docker 若将 Tomcat 映射到 **8082**，打开地图时加参数：  
  `embed.html?api=http://localhost:8082/water-quality/api`  
  或在 `app.js` 中修改默认 `API_BASE`。

---

## 4. 后端 REST 与数据表

- **communes**：`code_insee`, `nom_commune`, `departement`（无 lat/lon 时前端用 GeoJSON 质心）。
- **prelevements**：`id`, `code_insee`, `referenceprel`, `dateprel`, `heureprel`, `conclusionprel`；与 communes 通过 `code_insee` 关联。
- **resultats_analyses**：`prelevement_id`, `parametre`, `valeur_mesuree`, `limite_legale`；与 prelevements 通过 `prelevement_id` 关联。

前端期望的 JSON 字段名与后端模型一致（camelCase）：`codeInsee`, `nomCommune`, `dateprel`, `valeurMesuree`, `limiteLegale` 等。

---

## 5. 前端三种视图模式

1. **Départements (regions)**  
   请求 `map-data?mode=regions`，得到市镇级 `features`，用 `frontend/data/communes.geojson` 按 INSEE 着色；若失败则回退到 `departements.geojson` 按部门着色。

2. **Communes (carte)**  
   请求 `communes`，将返回的市镇列表转成 `features`，同样用 communes.geojson 画多边形。

3. **Communes (points)**  
   请求 `communes`，用 API 的 `latitude/longitude` 或 GeoJSON 质心画圆点。

---

## 6. 小结

- 所有“地图 ↔ 后端 ↔ 数据库”的交互都是：**前端 fetch(API_BASE + path)** → **后端 Resource → Service → DAO** → **MySQL**。
- 改端口或上下文时，只需改前端 `API_BASE`（或 URL 参数 `api=`）与后端部署一致即可。
- 详细接口说明见项目根目录 `frontend-backend.md` 与 `ARCHITECTURE.md`。
